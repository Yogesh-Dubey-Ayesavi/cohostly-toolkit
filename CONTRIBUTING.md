# Contributing

Thanks for helping. Keep changes small and say what behaviour changes.

1. Open an issue first for anything larger than a typo or a one-file fix.
2. Branch from `main`. One logical change per pull request.
3. Run the package's own checks before you push (see `CLAUDE.md` for the commands).
4. A change to a skill must keep `name` equal to its folder name, keep `SKILL.md` a short router, and put detail in `references/`.
5. A change to a published package needs a `CHANGELOG.md` entry.

By contributing you agree your work is licensed under Apache-2.0, the same as the repository.
